# Crysis2VR / C2VR — EVIDENCE BOUNDARY

Updated: 2026-08-31.

This file defines the hard boundary between locked knowledge and ongoing COLD research across global quality/scale control and role-specific R1/R2/R3/R4 lines.

## Two independent axes
Every claim carries an evidence class and a promotion scope.

Evidence class:
1. `LIVE_RESULT_EXACT` — executed exact-retail RESULT/capture with valid baseline and interpretable causal outcome.
2. `TARGET_STATIC_EXACT` — exact-target bytes, disassembly, xrefs, ABI, structures, symbols or deterministic package/source audit.
3. `PRESERVED_TARGET_SOURCE` — preserved source from an exact established runtime lineage.
4. `DONOR_BETA_HINT` — donor/beta/debug/SDK/analogous-project evidence from a non-identical build.
5. `PLAN_SUMMARY_PREPARED` — prose, ticket, prepared build or hypothesis not independently verified.

Promotion scope:
- `GLOBAL_LOCKED` — protected project fact/baseline.
- `ROLE_PROVEN` — proven only inside one role/claim boundary.
- `COLD_ONLY` — exact/strong COLD fact or inference that may narrow UNKNOWN/NEXT but may not rewrite locked runtime truth.
- `CANDIDATE_ONLY` — candidate generator only.

## Promotion law
- Clean exact LIVE promotes only the exact claim/scope demonstrated.
- Exact static/source evidence may prove bytes, ABI, control-flow and layout. Runtime ownership, visual behavior, cadence, temporal ownership or causal effect remains `COLD_ONLY` until execution closes that edge.
- Donor/beta evidence cannot promote an exact retail C2 fact by itself.
- Prepared package/ticket/summary is not evidence that behavior executed.
- User headset verdict proves the observed visual behavior/acceptance of that exact run, not hidden renderer ownership by itself.

## Contamination barrier
COLD work must not silently rewrite the protected transport/quality baseline, `GLOBAL_LOCKED` facts, exact executed PASS/FAIL, closed FALSIFIED paths or another role's `ROLE_PROVEN` claim.

COLD may add exact static facts, rank candidates, narrow UNKNOWN, define the next single-primary-fact experiment and record conflicts.

If COLD conflicts with locked evidence, keep the locked evidence unchanged and record `CONFLICT_WITH_LOCKED`; resolve with exact reconciliation, not summary prose.

## Cross-role import
Global quality/scale, R2 replay and R3 graph evidence are separate scopes. Cross-role evidence is `BORROWED_EVIDENCE` until independently proven for the receiving claim.

## FALSIFIED reopening
Reopen only on materially contradictory exact-target evidence at the same causal layer or stronger. Donor analogy, prepared build or differently scoped COLD inference is insufficient.

## Storage law
- Locked facts stay in canonical `PROVEN/STATE/EVIDENCE` documents.
- Ongoing COLD work belongs under `docs/COLD/` or a role-scoped document marked `SCOPE=COLD_ONLY`.
- Sync/portfolio docs are navigation views and never outrank exact evidence.

## Promotion record
Before promotion record: `CLAIM_ID`, exact target/build, role, prior/new scope, artifact/source identity, PASS/FAIL, baseline status, contradictions resolved and authoritative docs updated.

No promotion by wording drift.
